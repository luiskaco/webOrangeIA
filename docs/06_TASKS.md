## Incidente en producción — robots.txt comprometido y sitemap roto (2026-08-20)
- [x] Cliente reportó un checklist de validación (sitio caído 404, robots.txt limpio, llms.txt UTF-8, redirects 301, sitemap 200 OK) supuestamente ya resuelto por soporte del hosting — verificado cada punto directo por HTTP contra `orange-la.com`, no se asumió el reporte como válido.
- [x] Confirmado OK: sitio sin 404 (5 páginas internas probadas), `llms.txt` con UTF-8 correcto, los 3 redirects 301 (http→https, www→no-www, trailing slash) funcionando.
- [x] **Encontrado real, no reportado**: `robots.txt` seguía con 19 entradas `sitemap-hot-XXXXXXX.xml` inyectadas — patrón típico de malware SEO en WordPress comprometido. Es un archivo físico en la raíz del hosting (no lo genera WordPress dinámicamente). Los archivos spam individuales ya daban 404 (limpiados en algún punto), pero el `robots.txt` en sí nunca se había reemplazado. Cliente lo reemplazó por FTP/File Manager con contenido limpio (`User-agent: *` / `Disallow: /wp-admin/` / `Sitemap: https://orange-la.com/sitemap_index.xml`) — verificado con cache-buster tras el cambio, `Last-Modified` actualizado, contenido limpio confirmado.
- [x] **Encontrado real, no reportado**: `sitemap_index.xml` de Rank Math daba 404 (el reporte decía 200 OK). Causa: rewrite rules de WordPress sin regenerar tras la migración. Fix: Ajustes → Enlaces permanentes → Guardar (sin cambios) — regenera las reglas. Verificado 200 OK tras el fix.
- [ ] **Recomendado, no ejecutado**: dado que hubo evidencia de una inyección de malware SEO pasada (aunque ya inactiva), vale una revisión de seguridad completa en producción — buscar mu-plugins o archivos no reconocidos, usuarios admin no reconocidos, tareas cron sospechosas. No se hizo en esta sesión, solo se resolvieron los síntomas visibles (robots.txt + sitemap).
